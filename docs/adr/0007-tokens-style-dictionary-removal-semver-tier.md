# ADR-0007 — `style-dictionary` removal from `@j0nathan-ll0yd/tokens` is MINOR, not MAJOR

## Context

PR #164 (`fix(tokens)!: stop leaking style-dictionary into consumer runtime deps`) removed `style-dictionary` from `packages/tokens/package.json` `dependencies`, retaining it as a single `devDependencies` entry, and shipped `@j0nathan-ll0yd/tokens` 2.0.0 → **2.1.0** (minor). The conventional-commit `!` marker asserts BREAKING (semver MAJOR), so the marker and the applied bump contradict each other; issue #180 (Atlas decision 0026, MEDIUM) asked which one is right. The recorded justification — that this was "a phantom hoisted transitive" — is **imprecise and was not taken at face value**: `style-dictionary` was a genuinely _declared_ runtime dependency of the published package, not a hoisting artifact. The published 1.0.0 and 2.0.0 manifests both carry `"dependencies": {"style-dictionary": "^5.4.4"}`, confirmed from registry metadata baked into the web consumer's `package-lock.json` (`node_modules/@j0nathan-ll0yd/tokens` @ 2.0.0), and because that consumer installs with **npm** (flat hoisting, not pnpm's strict layout) `node_modules/style-dictionary` is physically present and resolvable in its tree. So a consumer _could_ have phantom-imported it, which is the only route by which the removal could break anyone. Three facts close that route: (1) nothing in the shipped payload imports it — `files[]` is `dist` plus seven `src/*.css` files, `dist/tokens.js` contains zero `import`/`require` statements, and the sole occurrence of the string is the metadata value `"engine": "style-dictionary@5"` in `dist/build-report.json`; (2) no consumer imports it — the web app (the only JS consumer; iOS is SPM-only) has zero references across `.ts/.tsx/.js/.mjs/.cjs/.astro/.json/.yml` outside its lockfile, and does not declare it directly; (3) GOVERNANCE §6.2(5) defines MAJOR as "token rename or removal, component removal, SPM product rename, breaking type changes in `@j0nathan-ll0yd/schemas` — **requires consumer code changes**," and none of those apply here.

## Decision

**The MINOR bump was correct; the `!` marker was overstated.** Semver governs a package's public API, and a dependency tree is not part of it — the only breakage path was an undeclared phantom import, which no consumer has and which is outside the supported contract by ecosystem consensus. Measured against this repo's own version contract, the change requires no consumer code change and matches none of the enumerated MAJOR triggers. On a strictly literal reading of §6.2(5) the change is arguably a **patch** ("bug fix, no token name changes, no API changes" — the commit is a `fix`), since MINOR is defined by additions; MINOR was the conservative call in the safe direction and **stands as published**. Because 2.1.0 (and the 2.1.1 successor) already shipped, this is a **record correction only**: no retroactive republish, no corrective MAJOR changeset, no hand-edited versions. The reconciliation is this ADR plus a pointer note on the 2.1.0 entry in `packages/tokens/CHANGELOG.md`.

## Consequence

Future audits that spot the marker/tier contradiction in #164 have a durable answer and should not re-flag it; the CHANGELOG entry that an auditor reads first now links here, and the "phantom hoisted transitive" phrasing is corrected to the accurate one — a declared-but-never-imported runtime dependency. `style-dictionary` remains a `devDependencies` entry of `packages/tokens` and a root devDependency; it must not return to `dependencies`, since the shipped payload is pure CSS/JSON/JS-constants/Markdown and imports nothing at runtime. The general rule this records: a conventional-commit `!` must agree with the changeset tier that ships with it, and where they disagree the tier justified by GOVERNANCE §6.2(5) wins. That agreement is currently unenforced — no gate cross-checks the `!` marker against the changeset bump — so a mechanical check (commit-lint or a changeset-aware CI rule, alongside the existing export-surface rule) is the open follow-up; this ADR is deliberately not a substitute for it.
