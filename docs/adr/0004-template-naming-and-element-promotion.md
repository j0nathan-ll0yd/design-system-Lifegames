# ADR-0004 — Template Naming & Element Promotion (BDFL)

## Context

The four slot-based screen shells admitted in ADR-0003 shipped named `*Scaffold` (`AuthScaffold`, `SettingsScaffold`, `ProfileScaffold`, `ListScaffold`) inside the `LifegamesTemplates` target — a name/target mismatch. Industry-wide, "Scaffold" denotes the persistent application SHELL (Material's `Scaffold`, Flutter's `Scaffold`: the app bar + nav + body frame), whereas these are per-screen TEMPLATES in the Atomic Design sense (the page-level layout a single screen instantiates). The real app shell in this codebase is `MainTabShell`. Separately, the OMD screen dogfooding (ADR-0001/0002) left three gallery-local molecule FORKS (`StatCardView`, `SettingRowView`, `InitialsAvatarView`) that now duplicate promoted DS molecules, and the screens still hand-built generic CTAs and lacked a detail/show template — the missing canonical pair to `ListTemplate`. Viable options for the rename were leaving the mismatch (cheap, but entrenches a misleading term), or aligning the type names to the target and reserving "Scaffold"/"AppShell" for the actual shell.

## Decision

Under P8 authority: (a) **rename** `*Scaffold` → `*Template` (`AuthScaffoldDefaultBackground` → `AuthTemplateDefaultBackground` likewise), and **reserve the terms "Scaffold" and "AppShell" for the genuine application shell** (`MainTabShell` and any future app-frame organism) — never for per-screen templates. Historical ADRs (0001–0003) keep their original narrative as the immutable record of the decision as made; only their code-symbol references are updated so links stay valid. (b) **Reduce `AuthTemplate` to three type-level generics** (`Branding`, `PrimaryAction`, `Footer`), erasing the backdrop to a stored `AnyView` via a generic designated initializer — a static full-bleed backdrop rarely re-renders, so the erasure is free in practice and keeps the template under Swift's ergonomic generic ceiling. (c) **Element-promotion decisions:** add `LGButton` (the missing DS CTA primitive: four variants × two shapes, semantic-token-only, ≥44pt, destructive pinned to `LGColor.accentRed`) and adopt it for the screens' generic CTAs (Account Sign Out, SampleFiles Sign Up Free / Sign In, FileDetail primary Download); remove the three OMD molecule forks and migrate their consumers to `LifegamesComponents.InitialsAvatarView`, `LifegamesComponents.SettingRowView`, and `MetricContentView` (under `.neonCard(accent:)`); add `DetailTemplate` (a brand-agnostic `hero` / `metadata` / `description` / `actions` slot template) as the canonical pair to `ListTemplate`, and dogfood it via `FileDetail`. The "Sign in with Apple" control stays HIG-locked and host-styled (never `LGButton`). The element-promotion override remains bounded by the same slot-purity rails as ADR-0003: `LifegamesTemplates` imports only `LifegamesComponents`, `LifegamesComponentsCore`, `LifegamesTokens`, and `SwiftUI` (purity gate: zero OMD / HealthKit / TCA / APIClient / widget imports).

## Consequence

The type name now matches the target and the Atomic Design tier; "Scaffold" is free to mean the app shell, removing a recurring naming ambiguity. `AuthTemplate` exposes a richer backdrop without a fourth generic, so hosts (Launch / Login) keep their layered washes while the type signature stays ergonomic. `LGButton` becomes the single CTA primitive, so future screens stop hand-rolling buttons; `DetailTemplate` completes the list↔detail pair, so a detail screen fills slots rather than rebuilding layout. Removing the molecule forks eliminates the drift risk of two diverging `SettingRowView`/`InitialsAvatarView` definitions. Two adoptions were deliberately NOT made and are recorded as friction: (1) the OMD neon section headers ("Activity", "Quality", "GUEST PREVIEW", per-group titles) did not adopt the existing `SectionHeader` molecule — its API bakes in a monospaced system font (conflicting with OMD's all-SpaceGrotesk type rule), a mandatory trailing divider (absent from every OMD header), and no accent parameter (most OMD headers are accent-tinted), so adopting it would have degraded the brand surface; (2) FileDetail's 4-up icon-tile secondary actions stayed app-local because they are a bespoke compact grid, not a standard horizontal CTA that `LGButton` expresses. All templates and `LGButton`/`DetailTemplate` remain `Experimental`; they advance to Beta/Stable per P7 as real product surfaces adopt them.
