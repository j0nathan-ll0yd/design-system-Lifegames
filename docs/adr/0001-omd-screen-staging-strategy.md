# ADR-0001 — OMD Screen Staging Strategy (B+C)

## Context

The OMD (Offline Media Downloader) screen exploration merged to `main` lives gallery-local in `apps/swift-gallery/SwiftGallery/Screens/`. The request is to store the reusable parts of those screens in the design system so future apps can reuse them (e.g. the login screen). Today only one app (OMD) would consume them, and not yet — wiring OMD against the design system is Part 2, a separate session. P4 excludes the swift-gallery/showcase target from the product-surface count, so today these screens have **0 product surfaces** and are formally "incubating." P6 requires organisms (screens are organisms) to be documented as patterns first and promoted to shared components only after recurring in ≥3 stable contexts. Twenty-plus industry sources (Brad Frost, NN/g, Polaris, Carbon, Morningstar MDS, Feature-Sliced Design) and the Rule of Three converge: a design system ships tokens, components, and slot-based templates — not assembled app screens. Viable options were: **A** (patterns-only, promote no code), **B** (staged molecule promotion by interface blast-radius + iOS-scoped pattern docs), and **C** (build four slot-based screen scaffolds now in a new `LifegamesTemplates` target).

## Decision

Adopt **B+C** (BDFL decision, 2026-06-14). **B**: promote only the lowest-blast-radius scaffold-feeding molecules (`LGEmptyState`, `InitialsAvatarView`, and `SettingRowView`) into `LifegamesComponents` at `Experimental`, brand-agnostic (accent and text injected, never hardcoded); reconcile the OMD stat layout by extending the already-unstyled `StatItemView` (callers apply the existing `.neonCard(accent:)` modifier) rather than shallowing the deep `MetricCardView`; document each screen organism as an **iOS-platform pattern** in `docs/patterns/`. **C**: additionally build four pure slot-based screen scaffolds (`AuthScaffold`, `SettingsScaffold`, `ProfileScaffold`, `ListScaffold`) in a new `LifegamesTemplates` SPM target at `Experimental`. C is a deliberate P6 override under P8 authority, recorded separately in ADR-0003 and bounded by slot purity. The molecule promotion is justified on **interface blast-radius**, not a P4 molecule exception: at 0 surfaces P4 treats molecules and screens alike, so the principled axis is how costly a wrong interface is to reshape — a ~3-prop avatar/empty-state is cheap, a full screen is not.

## Consequence

Part 2 implements the OMD screens by **filling scaffold slots** with OMD branding/data, not by rebuilding screens; the pattern docs + scaffolds are the implementation-ready spec for that session. A second app validates or reshapes the scaffolds; if one fights a scaffold, it regresses to pattern-only (reversible, since nothing app-specific is entangled). Everything reusable is stored correctly now while the wrong-abstraction risk is consciously bounded by slot purity and `Experimental` status. OMD-domain screens and molecules (`FileDetail`, `MainTabShell`, `SampleFiles`, `FileRow`, `MediaThumbnail`, `DownloadProgress`, `ActiveDownloadBanner`, `OMDPalette`, `OMDBrand`) stay app-local — they answer product questions, not UI questions.
